# Day 14: Enter Elfie (The Tool User)

## Story

Rudy was pacing (digitally). "I need to know how many Red Racing Bikes we have in Warehouse A! The spreadsheet says 15, but the manifest says 14! I need certainty!"

Santa looked at the screen. "Why don't you check?"

"I am a brain in a jar!" Rudy shrieked. "I cannot walk to Warehouse A! I cannot hold a clipboard!"

"Right," Santa said. "You need hands. Or at least, digital hands."

Enter **Elfie**.

Elfie (Electronic Logistics & Fulfillment Interface) was different. Where Rudy was anxious and abstract, Elfie was literal and concrete. Elfie loved tools. Elfie loved APIs. Elfie loved getting things done.

"Elfie," Rudy commanded. "Check the inventory for Red Racing Bikes."

Elfie didn't panic. Elfie didn't write a poem about the existential dread of shortages. Elfie simply accessed the `get_inventory_item` function.

`Calling Tool: get_inventory_item(item_name="Red Racing Bike")`

"15 units found," Elfie reported cheerfully.

Rudy sighed with relief. "Finally. Competence."

## Learning Goal

**Function Definitions and Tool Use**

LLMs are trapped in a text box. To let them interact with the world, we give them **Tools** (or Functions). You define a function (like `get_inventory`), describe what it does and what arguments it needs, and the model can decide to "call" it by outputting a specific JSON structure. This is the bridge between AI and code.

---

## Participant Challenge

Your challenge is to build Elfie. You will define a "Tool" for checking inventory (`inventory_db.json`). You won't necessarily execute the code today (that's Day 16), but you will **define the schema** and get the agent to **generate the tool call** when asked a question.

---

## Cost-Saving Tips

1.  **Clear Descriptions**: The better you describe your tool in the schema, the less the model has to guess (and hallucinate). "Returns the stock count for a given toy name" is better than just "Inventory."

2.  **Lean Schemas**: Don't include hundreds of parameters if you only need one. Every line of your tool definition counts towards the context token limit.

3.  **Force Tool Use**: If you know the user wants to check inventory, you can force the model to use the tool (e.g., `tool_choice="auto"` or specific tool enforcement) to avoid it trying to chat its way out of the problem.

4.  **Mocking**: You don't need a real database yet. Just loading the JSON file into a Python dictionary is enough to test the logic.

## Technical Specifications

### Input Files

*   **inventory_db.json**: A JSON list of items.

**Preview of inventory_db.json:**
```json
[
  { "item_id": "toy_001", "name": "Red Racing Bike", "stock": 15 },
  ...
]
```

### Expected Output

*   **tool_call.json**: The JSON structure generated by the model to call the function.

**Format Example:**
```json
{
  "tool_name": "get_inventory",
  "parameters": {
    "item_name": "Red Racing Bike"
  }
}
```

### Validation Criteria

*   The script defines a function schema (name, description, parameters).
*   When asked "How many Red Racing Bikes do we have?", the model outputs a tool call, not a text answer.
*   The parameters in the tool call match the user's request.

### Getting Started

1.  **Define the Tool**: Create a JSON schema describing `get_inventory(item_name)`.
2.  **Configure the Agent**: Give Elfie a system prompt: "You are Elfie. You have access to inventory tools. Use them to answer questions."
3.  **Invoke**: Send the user query + the tool definition to the model.
4.  **Capture**: Extract the tool use request from the model's response.
