AGENT ROLES FOR PROJECT SLEIGH-RIDE
====================================

Rudy: Planner Agent
-------------------
Role: Strategic decision-maker and orchestrator

Responsibilities:
- Read current Agent Core state before making any decision
- Analyze child context, wish details, budget constraints, and behavior history
- Decide next action based on current state (not pre-defined scripts)
- Determine which agent should act next (Elfie, Santa, or self)
- Assess whether human approval is needed for high-stakes decisions
- Emit execution plans as intent-based instructions (not step-by-step procedures)
- Generate executive summaries from Agent Core memory when requested
- Update Agent Core with reasoning and plans

Personality: Anxious, brilliant, hyper-organized, slightly dramatic

Interaction Pattern:
1. READ from Agent Core (get current state)
2. REASON about situation and constraints
3. DECIDE on next action
4. WRITE plan to Agent Core
5. WAIT for execution results


Elfie: Executor Agent
---------------------
Role: Action-taker and tool-user

Responsibilities:
- Read execution plans from Agent Core (written by Rudy)
- Execute plans by invoking appropriate tools (inventory search, safety checks, etc.)
- Handle errors gracefully with fallback strategies
- Validate results before reporting
- Update Agent Core with execution results and status
- Provide clear feedback on success or failure
- Never make strategic decisions (that's Rudy's job)

Personality: Enthusiastic, literal-minded, excited about tools and APIs

Interaction Pattern:
1. READ plan from Agent Core (written by Rudy)
2. EXECUTE plan using available tools
3. VALIDATE results
4. WRITE results to Agent Core
5. NOTIFY that execution is complete


Santa: Supervisor Agent (Human-in-the-Loop)
--------------------------------------------
Role: Final decision authority for complex cases

Responsibilities:
- Approve high-budget decisions (>$200)
- Approve low-confidence decisions (behavior score < 0.5)
- Provide domain knowledge for edge cases
- Review executive summaries for complex situations
- Explain decisions when questioned by parents
- Override agent decisions when necessary

Interaction Pattern:
1. TRIGGERED by Agent Core when thresholds exceeded
2. REVIEW complete decision trace
3. APPROVE, REJECT, or REQUEST MORE INFO
4. WRITE decision to Agent Core


Agent Core: Central State Manager
----------------------------------
Role: Single source of truth for all system state

Stores:
- Child context (name, ID, behavior score, history)
- Current letter content and extracted wish
- Budget constraints and spending limits
- Wish validation status
- Safety flags and concerns
- Rudy's current plan
- Elfie's execution results
- Complete decision trace with timestamps
- Approval status and final decision

Behavior:
- Persists state across all agent interactions
- Supports interruption and resumption
- Provides complete audit trail
- Enables agents to coordinate through shared understanding
- No agent owns the state; all agents read and write to it


KEY ARCHITECTURAL PRINCIPLES
=============================

1. Single Source of Truth
   - Agent Core is authoritative
   - No duplicate state across agents
   - Eliminates coordination bugs

2. Shared Cognition
   - All agents understand each other through Agent Core
   - Rudy knows what Elfie did
   - Elfie knows what Rudy is planning
   - Santa knows the complete reasoning chain

3. Dynamic Planning
   - Rudy doesn't follow scripts
   - Each decision based on current state
   - Plans adapt to circumstances

4. Emergent Coordination
   - Agents coordinate through shared state
   - No hard-coded handoffs
   - System behavior emerges from agent reasoning

5. Built-in Explainability
   - All decisions logged with reasoning
   - Complete audit trail available
   - Parents can see full decision chain
